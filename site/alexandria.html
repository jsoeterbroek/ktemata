Alexandria

Project Alexandria is how I keep books on the device: a small Python tool that turns Project Gutenberg ebooks into searchable ZIM archives, feeding my own curated shelf rather than a bulk dump of everything Gutenberg has ever scanned.

  • 128books on the shelf
  • 4,291chapters and sections
  • 397 MiBthe whole collection
  • 16Kiwix shelf categories

The name is the point. The library at Alexandria was not famous for owning every scroll in existence; it was famous for being chosen. A device that carries all of Gutenberg carries a warehouse — tens of thousands of titles, most of them unread, most of them not worth the bytes on a pack this size. Alexandria builds a shelf: a list I curate by hand, book by book, and can defend line by line.

This is my personal list, not a recommended reading list and not a curated canon for anyone else. The descriptor in the repository is my shelf as it stands — the books I actually want on my machine, with my choices about editions, metadata corrections and modern spelling. It is published because the tool is useful, not because the selection is. Fork it and put your own books in it.

What it does

Alexandria downloads the ebook HTML and its RDF metadata record from Project Gutenberg, splits the text into chapters, rewrites the internal links and pulls down the referenced images, then packs the result into a ZIM archive with libzim. A ZIM is the same container Kiwix already serves Wikipedia, maps and reference works from, so a converted book sits on the device beside them with the same search, the same reader and the same catalogue.

Input
a YAML descriptor — one entry per book, keyed by Gutenberg ebook number
Output
one .zim per book, plus a Kiwix library.xml for the whole shelf
Per book
a title page with metadata and a nested table of contents, one article per chapter, its images, and a reader stylesheet
Search
full-text and title indexes built in the book's own language
Covers
each book's own cover stored as a ZIM illustration, so Kiwix's catalogue shows it

Everything is written to a .part file and only renamed after libzim's integrity check and a main-entry check pass, so a failed build never replaces a good archive. Reruns skip books that already exist and open cleanly.

Size is dominated by illustrations, not text. The Count of Monte Cristo is 102 MiB with 124 chapters, Don Quixote 60 MiB with 138; the median book is under a megabyte. The whole shelf is 397 MiB — small enough to sit beside Wikipedia and the maps without competing for the drive.

What the tool adds over a plain ebook

Modern English, on request

Some Gutenberg texts are archaic enough that the reading gets in the way: Burton's Thousand Nights alone runs to thousands of "thou", "hath" and "quoth". For those entries the descriptor sets modernize: true and the prose is rewritten before the book is split — thou knowest becomes you know, hath becomes has, quoth becomes said. On my shelf all ten volumes of the Thousand Nights use it — the only books that needed it.

The rewrite is rule-based and deterministic, not a machine translation, and verb stems are checked against the words the book actually uses, so lookalikes stay put — "the best guest", "his teeth", "the art of war". Markup, attributes, links and proper names are untouched; only text nodes change. Spelling and dialect stay as printed.

Editions that were never HTML

A few ebooks ship only as PDF or LaTeX — the Tractatus Logico-Philosophicus, for one. Those are converted to parseable HTML and split on headings and proposition numbers, then follow the normal pipeline. Audio-only recordings are reported as unbuildable rather than packed as a track list.

Metadata that is actually right

Gutenberg's RDF is mostly good and occasionally wrong: ebook #68282 (The Call of Cthulhu) ships a metadata record belonging to a different book, and the Thousand Nights volumes credit Burton only as translator. The descriptor lets me override the display title and author, and the library summary is regenerated from those — so my shelf says what I decided it says.

Using it

make               # help: every target
make build         # convert missing books (skips ZIMs that already exist)
make build_all     # rebuild every book, overwriting existing ZIMs
make only ID=11    # (re)build one book
make list          # books in the descriptor
make library       # refresh output/library.xml
make verify        # integrity-check output/*.zim
make test          # offline test suite
make check         # lint + format check + tests

A descriptor entry is a Gutenberg id plus whatever overrides the edition needs: 

books:
  - id: 10
    title: "The King James Version of the Bible"
  - id: 766
    title: "David Copperfield"
    author: "Charles Dickens"
  - id: 3435
    title: "The Book of the Thousand Nights and a Night — Volume 01 (of 10)"
    modernize: true

Point Kiwix at the generated library and the whole shelf is browsable: 

make library
kiwix-serve --library output/library.xml

On the device

Ktemata already installs kiwix-serve and serves the library on :8080 (work/scripts/post-install.sh --hotspot makes it reachable at 10.10.10.1:8080 from a phone or laptop). Adding books is therefore a copy and a restart: drop the .zim files into /srv/kiwix/zim, rebuild library.xml — the service does that on start — and the catalogue picks them up. There is no second reader to install and no import step; a converted book is just another archive beside Wikipedia and the maps.

A curated shelf is the difference between a library and a warehouse. The device has a 512 GB drive and room for roughly 477 GiB of content. Filling it with everything downloadable would spend that budget on books nobody opens; picking 128 books spends 397 MiB and still leaves Wikipedia, the maps and the reference works the space they need.

The code

Alexandria is a separate project from Ktemata — its own repository, its own test suite, no shared code with the CAD: github.com/jsoeterbroek/alexandria.

It is plain Python with no service to run and no database: a YAML descriptor in, ZIM files out. The modules follow the pipeline — gutenberg for metadata and covers, net for cached fetching, document for HTML into chapters and media, archaic for the modern-English rewrite, classification for the shelf categories, formats for PDF and TeX editions, zim and library for the output, and workflow and cli over all of it.

The descriptor that produced the numbers on this page is the one in that repository — my list, kept in version control, so every change to my shelf is a commit I can read back.
