# Pi Fluks r3 build

**r3 = r2 mechanical build + Phistone Mini Keyboard.** There is **no CAD or STL change**: r3 uses the same
`stl/` files and the same 137 × 72 keyboard support/window as r2. The difference is the keyboard, its
2.4 GHz/Bluetooth link and the corresponding Pi configuration.

## What is different from r2

| Item | r2 | r3 |
|---|---|---|
| Keyboard | Wired USB keyboard | **Phistone Mini Keyboard**, 2.4 GHz + Bluetooth 5.0 |
| Keyboard cable | Internal USB-A cable | None (2.4 GHz dongle) or none (Bluetooth) |
| Pi Bluetooth | Disabled (`dtoverlay=disable-bt`) | Optional: enabled only for the Bluetooth keyboard |
| Pi Wi-Fi | Disabled | Disabled |
| FireBeetle radios | Off | Off |
| Case/STLs | r2 | **Same as r2** |

The Phistone is the keyboard from the original r1 build guide: 134 × 74 × 12.7 mm, 84 g, 100 h battery
(backlight off), USB-C charging, RGB backlight and air-mouse gestures. Its body is close to the r2
keyboard support (137 × 72 mm), so it sits in the same place.

## Connect it

### Option A — 2.4 GHz dongle (recommended for boot/reliability)

1. Set the keyboard's side switch to **2.4G**.
2. Put the receiver in the **spare Pi USB-A port**. One Pi USB-A port is already used by the FireBeetle
   serial link.
3. No pairing or Bluetooth configuration is needed. The keyboard works at boot and in recovery.
4. Wi-Fi and Bluetooth can stay disabled.

### Option B — Bluetooth

1. Set the keyboard's side switch to **BT** and put it in pairing mode.
2. On the Pi, remove or comment out `dtoverlay=disable-bt` in `/boot/firmware/config.txt`, enable
   `bluetooth.service`, then pair and trust the keyboard with `bluetoothctl`.
3. Keep a **wired USB keyboard** for first boot, recovery and any pre-OS prompt. Bluetooth is not available
   until the OS/BlueZ stack is running.
4. Leave Wi-Fi disabled. The FireBeetle radios stay off.

## Practical notes

- **Fit:** the Phistone body is 134 × 74 × 12.7 mm; the r2 window is 130 × 67 mm and the support is
  126 × 69 mm. The r1 face was built around this keyboard, so it should fit the same way. Check the
  keyboard's side switch/USB-C port clearance before closing.
- **Side access:** the r2 face has `SIDE_CUTOUT=false`. Set the 2.4G/BT switch and charge the keyboard
  before final assembly, or add a small sealed side access later.
- **Layout:** the Phistone has a cramped, non-standard layout; Ctrl and punctuation are not where a normal
  keyboard puts them. Test it for terminal work before relying on it.
- **Battery:** 100 h with the backlight off; RGB and air-mouse use reduce that. Charge via USB-C before
  closing.
- **Security:** both Bluetooth and 2.4 GHz are wireless links. For sensitive/offline work, a wired USB
  keyboard is still preferable.

## Radio exception

This is the **only** intentional radio exception in the project. r2 and the default r3 setup keep Wi-Fi,
Bluetooth and the FireBeetle radios off; r3 may use the keyboard's 2.4 GHz dongle or the Pi's Bluetooth.
No hardware radio switch is added.
